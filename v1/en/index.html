Agents can write code.
Who tells them what to do next

Hand a requirement to an agent and it will produce a function that runs. But it does not know what comes next, does not know where the boundary is, and will not tell you which calls it made on your behalf. Once the context grows, the direction drifts, and you spend an afternoon reading what it changed.

The fix

Turn agent work into reviewable tasks

Every task is a Markdown file with a description, acceptance criteria, and an implementation plan. The agent writes down what it will do before it writes code, and waits for your approval. Tasks move into version control with the code, so they can be diffed, reviewed, searched, and archived.

Why Backlog.md

Four concrete outcomes: direction holds, review has handles, data stays local, knowledge accumulates.

Agents stop improvising

Each task carries a description, acceptance criteria, and an implementation plan. The agent states what it will do before it writes a line of code, and you read it before it runs.

Three review gates

Spec, plan, and result are approved separately. A wrong direction stops before the first line of code, not after a thousand line diff.

Your data never leaves the machine

Everything is stored in local Markdown files inside the project. No cloud account, no subscription, works offline, and Git is optional.

Every session compounds

The LLM Wiki turns tasks, docs, and decisions into a searchable project memory, so a new session never starts from zero.

Three steps to running

Initialize, decompose and plan, review and capture. Each step has a clear handoff.

01

Initialize a backlog

Run one command inside any Git repository and pick CLI instructions or MCP for your agent. You can also skip AI and use it as a plain task manager.

backlog init "My Awesome Project"
02

Let the agent decompose and plan

Describe the idea. The agent creates tasks with acceptance criteria, researches the codebase, writes the implementation plan, then stops for your approval.

Review point: read the description and acceptance criteria first, then approve the plan
03

Review the result and capture it

Read the diff, run the tests, check the acceptance criteria. Once it passes, write the summary and the knowledge lands in the Wiki as input for the next step.

One task per session, one task per commit

Features

Terminal, web interface, MCP, and CLI all read and write the same Markdown files, so you can switch at any time.

  • Local Markdown tasks — every item is a plain .md file you can diff, review, and search
  • Built for agents — works with Claude Code, Gemini CLI, Codex, Kiro, and any assistant that can call a CLI or MCP server
  • Terminal board — backlog board renders the current board right in the terminal
  • Modern web interface — backlog browser gives you a drag and drop board, rich forms, and live updates
  • LLM wiki knowledge base — an AI maintained pairing notebook with ingestion, query, and health checks
  • Memos quick notes — feed, calendar, and pinboard views with inline tags and task links
  • Tracking Gantt — planned and actual dates on two layers across five time grains
  • Graph queries — read only Cypher over the graph of tasks, docs, dependencies, and links
  • Live query blocks — embed read only SQL or Cypher in any Markdown body and render results in place
  • Chart blocks — mermaid and echarts fenced blocks for flowcharts and data charts, theme aware
  • File preview — high fidelity DOCX, XLSX, PPTX, and PDF preview inside the web interface
  • MIT licensed — free for personal and commercial use, on macOS, Linux, and Windows
