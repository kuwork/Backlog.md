# BACK-495 跟踪甘特图设计推理

## 原始需求

在现有甘特图（BACK-491）基础上，同时展示计划时间与实际时间，实现偏差追踪。

## 问题分解

1. **数据层**：任务已有 `plannedStart`/`plannedEnd`（BACK-401）和 `actualStart`/`actualEnd`（BACK-492），无需新增数据结构
2. **展示层**：如何在同一行上展示两组时间？
3. **交互层**：Tooltip、高亮、图例如何同时支持两组时间？
4. **依赖层**：箭头连接点应基于计划还是实际时间？

## 方案对比

### 方案 A：切换模式
- 一个全局切换按钮，在看板模式和跟踪模式间切换
- **优点**：实现简单，代码分支少
- **缺点**：无法同时对比计划与实际，失去跟踪意义

### 方案 B：双层叠加（选择）
- 底层实际条 + 上层计划边框，z 轴叠加
- **优点**：一眼可见偏差（提前、延期、正常），信息密度高
- **缺点**：CSS 实现复杂，需要处理颜色冲突

### 方案 C：并列条
- 同一行上下排列两个条
- **优点**：无颜色叠加问题
- **缺点**：行高增加，密集任务时垂直空间爆炸

## 关键设计决策

1. **计划边框使用斜线填充**：`repeating-linear-gradient(60deg, ...)`，与实际条的纯色形成明显视觉区分
2. **双层边框（2px+1px）**：制造厚度阴影感，使计划框在复杂背景下仍可辨识
3. **箭头颜色改为 gray-500**：避免与状态色实际条冲突
4. **左表默认显示实际时间**：用户最关心的"发生了什么"优先展示，计划时间通过开关切换
5. **最小宽度回退策略不变**：保证单日期任务在任何视图中都有可见宽度

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 斜线填充在暗色模式下不可见 | 暗色模式反色（白色细线 + 灰色粗线） |
| 实际条与计划框颜色叠加后难以辨认 | 使用 pointer-events-none 让点击穿透到实际条，保持交互明确 |
| 时间解析复杂导致性能问题 | 使用 useMemo 缓存 planPositions 和 resolvedTimes |

## 子任务拆分

- BACK-495.1：左表 + 时间解析引擎（数据准备）
- BACK-495.2：双层渲染（核心视觉）
- BACK-495.3：Tooltip + 图例 + 交互（用户体验）
- BACK-495.4：智能依赖箭头（边缘场景）
