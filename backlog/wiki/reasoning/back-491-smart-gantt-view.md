# BACK-491 规划痕迹：智能甘特图视图

## 原始需求

Backlog.md Web UI 缺乏时间维度可视化能力。任务模型已包含丰富的日期数据（`createdDate`、`plannedStart`、`plannedEnd`、`updatedDate`）和依赖关系，但无法以图形化方式呈现项目时间线。

## 问题分解

1. **数据层**：已有字段充足，无需新增数据结构
2. **解析层**：需要规则将不一致的日期数据解析为有效起止时间
3. **渲染层**：左侧表格 + 右侧时间线双面板布局
4. **交互层**：粒度切换、排序、依赖高亮、拖拽平移
5. **兼容层**：无计划日期任务不能消失，单日期任务不能压缩为细线

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 引入 DHTMLX Gantt / Frappe Gantt | 功能全面、开发快 | 增加依赖体积、定制受限、暗黑模式适配困难 | 拒绝 |
| **纯 React/CSS 自研** | 零依赖、完全可控、Tailwind 暗黑模式原生支持、与现有组件体系一致 | 开发量较大 | **采纳** |

## 关键设计决策

### 时间解析规则（强制优先级）
- 开始：`plannedStart` → `createdDate`
- 结束：`plannedEnd` → `updatedDate` → fallback
-  rationale：最大化利用已有数据，同时保证所有任务都有可视表示

### 最小宽度回退
- 日视图 4 小时视觉宽度：解决同天多任务重叠，同时保持"单日期"语义
- 年/季度视图固定 8px：确保在极大时间跨度下仍有可交互色块

### 依赖箭头
- SVG 绝对定位覆盖层而非 Canvas：与 React 渲染周期一致，便于事件绑定
- 立方贝塞尔曲线：视觉清晰，多依赖时通过水平引线错位防缠绕

## 任务拆分

1. 创建 `GanttView.tsx` 主组件（含时间线引擎、任务条、依赖箭头）
2. `App.tsx` 注册 `/gantt` 路由并传递数据
3. `SideNavigation.tsx` 添加导航项与图标
4. `src/server/index.ts` 添加服务端路由（SPA 刷新支持）
5. 四国语言补充 `gantt` 命名空间

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 大量任务时性能问题 | 仅渲染可视区域（未来优化），当前先实现功能 |
| 日期解析歧义 | 规则文档化，列表中以 `*` 标记回退任务 |
| 依赖箭头在复杂项目中缠绕 | 贝塞尔曲线 + 多依赖错位，后续可引入层分配算法 |
